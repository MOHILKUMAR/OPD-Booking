# 3. API and server-function specification

All browser calls go through `@supabase/supabase-js` with the **publishable** key. RPCs are
`POST /rest/v1/rpc/<name>` with named JSON arguments. Business errors come back as HTTP 400 with:

```json
{
  "code": "P0001",
  "message": "MQ_DUPLICATE_BOOKING",
  "hint": "This mobile number already has an active token…",
  "details": ""
}
```

`message` is a stable machine code. `hint` is safe to show to patients. `details` carries a sub-reason
where useful, for example `FULL` or `HOLIDAY` for `MQ_SESSION_UNAVAILABLE`. The client maps codes
to UI states in `src/lib/errors.ts`.

## Public (anon + authenticated)

| RPC / table                       | Arguments                                                                                                    | Returns                                                                                                                                                                                                |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `hospitals` (table)               | `slug=eq.<slug>`                                                                                             | hospital profile, hours, policies                                                                                                                                                                      |
| `departments`, `doctors` (tables) | standard filters                                                                                             | active rows only                                                                                                                                                                                       |
| `hospital_announcements` (table)  | —                                                                                                            | published and unexpired only                                                                                                                                                                           |
| `search_doctors`                  | `p_hospital_id, p_search?, p_department_id?, p_specialty?, p_available_only?, p_date?, p_limit≤50, p_offset` | `{ total, date, items: [doctor + department + sessions[]] }`, filtered and paginated on the server                                                                                                     |
| `get_sessions`                    | `p_hospital_id, p_from?, p_to? (≤15 days), p_doctor_ids?`                                                    | rows: shift, effective times, `session_status`, capacity, `remaining_online`, `bookable`, `unavailable_reason/message`, `current_token_no`, `next_token_no`, delay, fee, `payment_required`, `version` |
| `get_display_board`               | `p_hospital_id, p_department_id?`                                                                            | today's sessions (doctor, department, room, current/next token, status, delay) + display announcements. **No patient fields.**                                                                         |
| `queue_states` (table, Realtime)  | `id=eq.` / `session_date=eq.`                                                                                | PII-free live state                                                                                                                                                                                    |
| `get_booking`                     | `p_booking_reference, p_access_key?`                                                                         | booking view (masked name/phone, doctor, shift, hospital, payment/refund status, queue, `patients_ahead`, `estimated_wait_minutes`, `can_cancel`, last 5 notifications), or `null`                     |
| `cancel_booking`                  | `p_booking_reference, p_access_key?, p_reason?`                                                              | `{ booking_reference, status, refund_requested }`                                                                                                                                                      |

Rate limits (defaults, tunable in `app.config` without a deploy): `get_booking` allows 120 calls per
10 min per IP and 60 per 10 min per reference; `cancel_booking` allows 30 per 10 min per IP;
`book_token` allows 10 bookings per hour per session and 60 per hour per IP.

| `rotate_access_key`       | `p_booking_reference`                                                                               | new tracking key (owner only)                                                                                                                                                                                                                                                        |
| `mark_notifications_read` | `p_ids uuid[]`                                                                                      | own notifications                                                                                                                                                                                                                                                                    |

## Edge Functions (`supabase/functions`)

All functions:

- answer CORS only for `ALLOWED_ORIGINS`
- validate bodies with the same Zod schemas the UI uses (`_shared/schemas.ts`)
- authenticate the caller by verifying the `Authorization: Bearer <user JWT>` with Supabase Auth
- call `svc_*` functions with the secret key

| Function                | Auth                            | Request                                                                                  | Response                                                                                                                                                                                                                                                                |
| ----------------------- | ------------------------------- | ---------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `payments-create-order` | patient JWT                     | `{ shift_id, session_date, patient_name, patient_phone, patient_age?, idempotency_key }` | `{ key_id, order_id, amount_paise, currency, booking_reference, access_key, hold_expires_at, booking }`. `503 PAYMENTS_DISABLED` unless enabled; `409 ORDER_IN_PROGRESS` asks the client to retry.                                                                      |
| `payments-verify`       | patient JWT                     | `{ razorpay_order_id, razorpay_payment_id, razorpay_signature }`                         | verifies HMAC with `key_secret`, **fetches the payment from Razorpay** (order, amount, status), captures if only authorized, then `svc_confirm_payment`. Returns `{ outcome: CONFIRMED / ALREADY_CONFIRMED / REFUND_REQUIRED, booking_reference, token_no, status }`.   |
| `payments-webhook`      | `X-Razorpay-Signature` (no JWT) | raw Razorpay event                                                                       | verifies HMAC over the raw body, dedupes by `x-razorpay-event-id`, applies `payment.captured`, `order.paid`, `payment.failed`, `payment.authorized`, `refund.processed`, `refund.failed`. 200 for processed/duplicate/rejected events; 5xx only for retryable failures. |
| `payments-refund`       | admin JWT                       | `{ refund_id }`                                                                          | `svc_begin_refund` → Razorpay refund (`X-Refund-Idempotency`, normal speed) → `svc_finish_refund_request`. Status becomes PROCESSED only when Razorpay says so.                                                                                                         |
| `admin-create-staff`    | admin JWT                       | `{ hospital_id, email, password, full_name, role, doctor_id? }`                          | creates the Auth user (email confirmed), profile and role; audited with the admin as actor                                                                                                                                                                              |
| `housekeeping`          | `x-housekeeping-token`          | —                                                                                        | expires stale payment holds and old rate-limit rows. Use pg_cron instead if available.                                                                                                                                                                                  |
