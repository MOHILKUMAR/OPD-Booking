# 10. Security review (2026-10-16)

This is a self-review of the code as built, backed by automated tests. It is not a substitute for
an independent penetration test before real patient data is stored.

## Controls and their evidence

| Area                 | Control                                                                                                                                                                                                                                                                                                                                                                                                                                       | Evidence                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Data access          | RLS on every table; anon has no access to `appointments`, `payments`, `audit_logs`, `profiles`                                                                                                                                                                                                                                                                                                                                                | `tests/db/security.test.ts` "patient data privacy", "no direct writes"                                                                           |
| Writes               | Clients cannot write appointments, queue state, payments or audit logs directly. Only `SECURITY DEFINER` functions with explicit role checks can                                                                                                                                                                                                                                                                                              | `security.test.ts` (permission denied on update/insert/delete)                                                                                   |
| Function exposure    | Default `EXECUTE` revoked from PUBLIC/anon/authenticated; per-function grants; `svc_*` only for `service_role` **and** re-checked inside                                                                                                                                                                                                                                                                                                      | `security.test.ts` "internal and server-only functions…", "defence in depth"                                                                     |
| Privilege escalation | Roles derived from `user_roles` via `auth.uid()`; the browser never sends a role. Only admins can grant roles; the last admin cannot be removed                                                                                                                                                                                                                                                                                               | `security.test.ts` role tests, `MQ_LAST_ADMIN`                                                                                                   |
| Definer safety       | Every `SECURITY DEFINER` function sets `search_path = ''` and qualifies names                                                                                                                                                                                                                                                                                                                                                                 | migration review                                                                                                                                 |
| Patient identity     | No phone lookup. Tracking uses reference + 128-bit key; only the SHA-256 hash is stored; the key travels in the URL fragment and RPC body only; names and phones masked in the tracking view                                                                                                                                                                                                                                                  | `booking.test.ts`, `security.test.ts`, e2e "secret key is never sent in a URL"                                                                   |
| Booking integrity    | Server-side validation, server-computed fees, atomic allocation under a row lock plus unique constraints, duplicate policy index, idempotency keys                                                                                                                                                                                                                                                                                            | `booking.test.ts`, `concurrency.test.ts`, load report                                                                                            |
| Abuse                | Per-session, per-IP (Cloudflare `cf-connecting-ip`), per-phone-per-day limits; lookup and cancel limits; anonymous sign-in limits in Supabase Auth; optional Cloudflare Turnstile (Supabase CAPTCHA) on anonymous and password sign-ins, enabled by `VITE_TURNSTILE_SITE_KEY` + the Supabase setting; the token is used only for sign-in and never sent to the Edge Functions                                                                 | `booking.test.ts` rate limits; `tests/unit/security.test.tsx` and `pages.test.tsx` "Turnstile"                                                   |
| Payments             | Signature HMAC with constant-time compare, plus a server-side fetch of the payment (order, amount, status); amount compared with the DB; webhook raw-body HMAC; event-id dedupe; idempotent confirmation; never restores a cancelled booking; refunds only via gateway confirmation                                                                                                                                                           | `handlers.test.ts`, `razorpay.test.ts`, `payments.test.ts`, load report                                                                          |
| Mode separation      | `RAZORPAY_MODE` must match the key prefix (`rzp_test_` / `rzp_live_`)                                                                                                                                                                                                                                                                                                                                                                         | `handlers.test.ts` "config"                                                                                                                      |
| Edge Functions       | JWT verified by the gateway and again in code; CORS allow-list; body size limits; generic 500s (no internals); webhook returns 5xx only for retryable errors                                                                                                                                                                                                                                                                                  | `handlers.test.ts`                                                                                                                               |
| Audit                | Append-only (trigger blocks update/delete, except the explicit retention job for rows over 90 days); written in the same transaction; actor recorded; no patient name or phone stored                                                                                                                                                                                                                                                         | `queue.test.ts`, `security.test.ts` retention                                                                                                    |
| Secrets              | Only `VITE_*` public values in the bundle; `.env*` git-ignored; secrets in Supabase function secrets                                                                                                                                                                                                                                                                                                                                          | bundle scan (only SDK key-prefix check strings), `.gitignore`                                                                                    |
| Browser hardening    | CSP (self + Supabase + Razorpay + Turnstile's `challenges.cloudflare.com` only), HSTS, `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `Referrer-Policy: same-origin`, no inline scripts                                                                                                                                                                                                                                                   | `public/_headers`                                                                                                                                |
| Staff session        | Supabase Auth, refresh-token rotation, staff can change their temporary password; optional TOTP two-factor authentication per account (enrol/remove dialog, code step after the password); once an account has a verified factor, staff routes, the database role helpers (every RLS policy and staff function) and the staff Edge Functions require an `aal2` token; staff UI routes guarded, and every staff action re-authorized in the DB | `RequireStaff`, e2e "staff and admin areas require sign-in", `security.test.tsx` "two-factor", `tests/db/mfa.test.ts`, `handlers.test.ts` "aal2" |
| Dependencies         | `npm audit`: 0 vulnerabilities (prod and dev) on 2026-10-16                                                                                                                                                                                                                                                                                                                                                                                   | CI step recommended                                                                                                                              |

## Residual risks (accepted for the MVP; tracked)

| Risk                                        | Impact                                          | Mitigation now                                                                                                                                                                                                                                                                                                                           | Next step                                                        |
| ------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| No OTP: anyone can book with any name/phone | fake or blocking bookings                       | duplicate and phone/day/IP/session limits, walk-in reserve, identity check at the desk; Turnstile when configured                                                                                                                                                                                                                        | optional paid SMS/WhatsApp OTP behind the notification interface |
| Anonymous sign-in abuse                     | MAU and booking spam                            | Supabase per-IP limit (30/h); Turnstile widget built in, off until `VITE_TURNSTILE_SITE_KEY` and Supabase CAPTCHA are set                                                                                                                                                                                                                | turn it on for every hosted deployment (free; deployment.md §2)  |
| Staff accounts without MFA                  | account takeover                                | strong temporary passwords, password change, audit trail; TOTP two-factor authentication (opt-in per account); for enrolled accounts the staff UI, the database role helpers (RLS and staff functions) and the `admin-create-staff` / `payments-refund` Edge Functions require `aal2`, so a password alone gets no staff data or actions | make enrolment mandatory for admins                              |
| Shared-IP rate limits                       | legitimate users blocked on hospital Wi-Fi      | configurable `app.config` limits                                                                                                                                                                                                                                                                                                         | monitor `MQ_RATE_LIMITED` in logs                                |
| Free-tier: no backups, project pausing      | data loss, downtime                             | manual dumps (operations.md)                                                                                                                                                                                                                                                                                                             | paid plan before go-live                                         |
| Realtime message quota                      | live updates degrade to polling                 | polling fallback, filters per session                                                                                                                                                                                                                                                                                                    | Realtime Broadcast on token change only                          |
| `style-src 'unsafe-inline'` in CSP          | slightly weaker CSP                             | no inline scripts; React escapes output                                                                                                                                                                                                                                                                                                  | move to hashed styles if the UI libraries allow                  |
| DPDP compliance not reviewed                | legal                                           | minimal data collected, masking, audit                                                                                                                                                                                                                                                                                                   | legal review, privacy notice, retention policy                   |
| Tracking link forwarded by the patient      | token, doctor and time visible to the recipient | masked identity, owner can rotate the key                                                                                                                                                                                                                                                                                                | none needed                                                      |
